Агент, который живёт в терминале

Опишите задачу обычными словами. cdx прочитает ваш проект, поправит файлы и выполнит команды на машине, где вы его запустили, - и спросит разрешение перед каждым изменением.

$ sudo apt install ./cdx_<version>_amd64.deb

Для чего это используют

Это не чат рядом с терминалом: он работает в текущем каталоге на реальной машине - читает файлы, запускает команды и показывает, что изменил. Большая часть примеров ниже - обычная работа админа.

Разобраться в унаследованном коде

"Объясни, что делает этот сервис и какие порты слушает." cdx обходит проект и отвечает со ссылками на файлы и строки, а не догадками.

Починить старые скрипты

"Скрипт сборки собирает по одной цели - пусть собирает пять." На выходе дифф, а не переписанный файл: те же флаги, те же имена, поменялись только циклы.

Работа с юнитами и логами

"Почему контейнер перезапустился в 3 ночи?" Читает journald, юниты и конфиги, затем называет причину и предлагает исправление.

Автоматизировать рутину

"Напиши systemd-юнит для этого бинарника, поставь лимиты, включи." Команды выполняются только после вашего подтверждения.

Настоящая сессия целиком

Реальная сессия, записана на обычной скорости и ускорена в 2.5 раза: скрипт сборки на 16 целей переделывается на пять параллельных сборок.

Время сессии: 2 мин 11 с, 15 шагов. Модель - выбранная по умолчанию; на записи подтверждения разрешений были выданы заранее.

Настоящий пример: build-all.sh

build-all.sh из Go-проекта собирает шестнадцать платформ одну за другой, потом варианты с GStreamer, потом цели под Android. На ноутбуке это перерыв на кофе, на сборочном сервере - простой ядер.

Как он устроен

Один бинарник: CLI, через который вы ставите задачи, и демон, который он поднимает в фоне. Каждая возможность - плагин, поэтому ядро остаётся маленьким: транспорт, хранилище, рантайм плагинов, цикл сессии.

Спрашивает, прежде чем действовать

Каждая правка, каждая команда и каждый путь вне рабочего каталога проходят через проверку разрешений. Пока вы не ответили, ничего не выполняется.

В запросе видно инструмент, точную команду и класс разрешения до того, как вы ответите. Enter выбирает вариант по умолчанию - "разрешить один раз"; остальные варианты дают разрешение на сессию, на запуск демона или навсегда.

По классам действий

Чтение, правки и команды shell имеют allow, ask или deny. По умолчанию разрешено только чтение, а всё, что меняет данные на ПК, спрашивает.

Без песочницы, осознанно

cdx работает с реальной машиной под вашим пользователем, а не в изоляции. Модель может ошибиться - и ошибочная команда сломает что-то по-настоящему. Запускайте cdx в Docker или на виртуалке, чтобы не сломать ПК.

Каждую команду подтверждаете вы

cdx не ведёт список "плохих" команд - опасной может быть любая. По умолчанию перед запуском он показывает точную команду, рабочий каталог и все внешние пути. Вы сами подтверждаете то, что будет выполнено.

Локально по умолчанию

У cdx есть веб-панель, и по умолчанию она доступна лишь с этой же машины (127.0.0.1). API требует токен - он создаётся при первом запуске. Для общего доступа есть CDX_ALLOW_REMOTE_HOST, он отключает эти проверки.

Установка

Пакеты для i386, x86_64, armv7 и aarch64 собираются к каждому релизу. Берите тот, который понимает ваш дистрибутив.

Debian / Ubuntu (.deb)

Файл cdx_<version>_amd64.deb возьмите на странице релизов.

sudo apt install ./cdx_<version>_amd64.deb
Fedora / RHEL / openSUSE (.rpm) 
sudo dnf install ./cdx-<version>-1.x86_64.rpm
Alpine (.apk)

Пакет не подписан, поэтому нужен флаг.

sudo apk add --allow-untrusted ./cdx_<version>_x86_64.apk
Любой Linux (zip + install.sh) 
unzip cdx_<version>_linux_x86_64.zip -d cdx
sudo ./cdx/install.sh          # /usr/bin/cdx и /usr/share/cdx/plugins
Из исходников

Нужны Go 1.27+ и Node.js 22+, чтобы собрать бинарник и панели.

make                 # веб-интерфейс, панели плагинов, бинарник
sudo make install    # /usr/bin/cdx и /usr/share/cdx/plugins

Первый запуск

Поднимает демон и открывает веб-интерфейс, где вы добавляете провайдера и модель.

cdx --config

Просто спросить

Работает в текущем каталоге и сохраняет сессию для следующего вопроса. Демон поднимается по требованию.

cdx "объясни этот пакет"

Демон

Держит сессии, провайдеров и права в фоне, пока вы работаете.

cdx daemon status
